Elevate appcore: architecture overview

Appcore is the Angular 14 single-page application that powers both the Elevate desktop app (Electron) and the Elevate web extension for Strava. This set of pages documents how it is built, how data flows through it, and where it is strong or fragile. It is written to be used as working context by engineers and by AI coding assistants.

For AI assistants

Read the AI working guide before changing code. The single most important fact: one source tree compiles into two different apps. Angular CLI fileReplacements swap the boot module, the target module and the environment file per build. A change that compiles for one target can break the other. Always check both desktop-* and extension-* variants of whatever you touch.

What appcore is

The repository elevate is a mono-repo with three projects. Appcore is the shared UI and domain layer. The two other projects are thin hosts that embed the compiled appcore bundle.

ProjectRoleHow it uses appcore
appcore/Angular SPA and the shared TypeScript library @elevate/shared in appcore/modules/shared.It is the product. Built with ng build --configuration=desktop|extension.
desktop/Electron main process: window management, connectors (Strava API, local FIT/GPX/TCX files), activity computation workers, backups on disk, auto-update.Loads the appcore bundle in the renderer window. Talks to it over Electron IPC through a preload bridge exposed as window.api. Imports @elevate/shared through tsconfig path aliases.
webextension/Manifest V3 Chrome extension that injects extra stats into strava.com and syncs activities by scraping Strava.Serves the appcore bundle as its options page (app/index.html). Shares chrome.storage.local with it and sends CoreMessages over chrome.runtime messaging.

Glossary

TermMeaning in this codebase
Build targetBuildTarget.DESKTOP or BuildTarget.EXTENSION, read from environment.buildTarget.
Target moduleTargetModule: the per-target service bindings, swapped by file replacement. Imported by SharedModule.
Boot moduleTargetBootModule: the per-target shell components, error handler, load service and app service. Imported by AppModule.
ActivityThe main entity (modules/shared/models/sync/activity.model.ts). Holds computed stats, laps, flags and the athlete snapshot used to compute it.
StreamsPer-second sensor arrays (time, distance, HR, power, lat/lng...). Stored separately, compressed with lz-string as DeflatedActivityStreams.
Dated athlete settingsAthlete physiology (max HR, FTPs, weight...) valid from a since date. Exactly one entry has since: null meaning "forever", the oldest fallback.
Athlete snapshotThe athlete settings resolved for one activity date, frozen into the activity. Used to detect when activities need recalculation.
Settings lackAn activity was computed while a needed threshold (for example FTP) was missing. Flag settingsLack: true.
ConnectorDesktop activity source: STRAVA (API) or FILE (local folder). Implemented in the desktop main process.
RecalculationRe-running the compute engine on stored activities and streams, through IPC on desktop.
InsightsAnonymised activity data the desktop app uploads to the Elevate backend.
MachineThe desktop installation identity (id and key) used to authenticate to the Elevate backend.
