Data and persistence

All athlete data lives in a single LokiJS in-memory database owned by the Angular app. A persistence adapter flushes it to IndexedDB on desktop or to chrome.storage.local on the extension. Small settings live in three other key-value stores. This page documents every store, the access layers and the backup and migration machinery.

DataStore

File: src/app/shared/data-store/data-store.ts. Key behaviours:

  • Single database named elevate, created in the abstract constructor through initDatabase(). Options: autoload: true, autosave: false, throttledSaves: true, env: "BROWSER".
  • Load signal: dbEvent$ is a ReplaySubject<DbEvent>. The autoload callback emits LOADED, or errors the subject. SAVED is declared but never emitted.
  • Collection resolution: resolveCollection(def) caches collections in a map, creates missing ones with the def options, and re-applies indices and unique fields every time the cached collection is dirty.
  • Every write persists the whole database. insert, update, put, remove* and clear mutate the collection synchronously and then call persist(waitSaveDrained), which calls db.saveDatabase(). On desktop the incremental adapter only writes dirty chunks. On the extension the adapter serialises every collection to chrome.storage.local.
  • Reads are synchronous wrapped in promises. find, findOne, getById and count return Promise.resolve(...) of Loki results. Returned documents are live Loki objects: mutating them mutates the in-memory database without persisting.
  • findOne inserts a default. If no document matches, findOne inserts the DAO default value into memory and returns it, without persisting. Singleton collections (athlete, user settings, sync date time) rely on this to self-initialise.
  • put = upsert keyed on the first unique field of the collection, or $loki if none. It merges with _.assign into the existing doc.
  • Id field: getById, removeById and put use collection.uniqueNames[0]. Collections without a unique field fall back to the internal $loki id.
  • Debug globals: after load, window.db is set in all builds, and window.data (raw collection arrays) in non-production builds.
  • Backup compatibility: static isBackupCompatible(version) compares with environment.minBackupVersion through semver.
  • Cleaning: static cleanDbObject and cleanDbCollection delete the $loki and meta fields before export. They mutate their argument.

The two production adapters

Desktop: IndexedDB incremental

  • lokijs/src/incremental-indexeddb-adapter.
  • Splits collections into chunks and writes only changed chunks.
  • Quota comes from navigator.storage.estimate(), effectively large.
  • Data lives in the Electron renderer profile (user data folder). Main process has no direct access.

Extension: LokiChromeAdapter

  • Defined inline in extension-data-store.service.ts.
  • Save parses the full JSON dump and writes one storage key per collection name.
  • Load reads all keys and rebuilds a database object. Any non-collection key in storage would be treated as a collection.
  • resolveCollection is overridden to call flushChanges() every time.
  • Usage is reported against chrome.storage.local.QUOTA_BYTES. The manifest requests unlimitedStorage, so the real limit is disk space.
  • The webextension scripts write to the same storage. They notify the app with ON_EXTERNAL_DB_CHANGE, which triggers dataStore.reload().

BaseDao

File: src/app/shared/dao/base.dao.ts. Subclasses implement getCollectionDef() and getDefaultStorageValue(). The constructor calls init(), which throws if no collection def is returned. Every method delegates to the DataStore with the DAO's collection def. Writes default to waitSaveDrained = false. removeMany throws NotImplementedException. chain() exposes a raw Loki Resultset for advanced queries (used by ActivityService.countByType with mapReduce).

Domain model essentials

Shared models live in modules/shared/models and are used by appcore, desktop main and the extension.

  • Activity (models/sync/activity.model.ts) extends BareActivity (id, name, type, start and end times and timestamps, manual, trainer, hasPowerMeter, commute...). It adds athleteSnapshot, stats: ActivityStats (speed, pace, power, heart rate, cadence, grade, elevation, dynamics, stress scores), srcStats (values reported by the source), laps, connector, hash, settingsLack, flags, extras, audit times. Static helpers classify sports (isRide, isRun, isSwim, isPaced...).
  • Timestamps: startTime and endTime are ISO strings. startTimestamp and endTimestamp are seconds, not milliseconds. Sync date times are milliseconds. Code converts with / 1000 and * 1000 in several places.
  • Streams (models/activity-data/streams.model.ts): arrays per sensor. Streams.deflate() and Streams.inflate() use lz-string base64 over JSON. StreamProcessor.handle(mode, params, streams) prepares streams for compute or display.
  • AthleteModel: gender, names, birth date, practice level, sports, datedAthleteSettings[]. Invariant: exactly one entry has since: null, and no two entries share a since. AthleteService.validate() enforces it.
  • AthleteSnapshot: gender, age at activity date, resolved AthleteSettings. equals() compares max and rest HR, FTPs, LTHRs, weight, swim FTP, age and gender.
  • AthleteSnapshotResolver (resolvers/athlete-snapshot.resolver.ts): sorts dated settings newest first and returns the first whose since is on or before the activity date, the forever entry being the floor.
  • UserSettings (models/user-settings/user-settings.namespace.ts): BaseUserSettings (units, warnings, zones) plus DesktopUserSettings (map type and token) or ExtensionUserSettings (about 40 strava.com display toggles, localStorageMustBeCleared).
  • Zones: UserZonesModel serialises zone arrays per metric. ZoneDefinitionModel describes the editable metric.

Backup and restore

Desktop (desktop/backup/desktop-backup.service.ts)

backup(outputDirectory, version) → Subject<BackupEvent>
  1. pick non-empty collections from desktopDataStore.db.collections
  2. IPC send backupInit(targetPath)            main opens a gzip writer, file "<date>-v<version>.elv"
  3. writeObject(metadata {version,totalDocs})
  4. for each collection, chunks of 10 docs:
       clean $loki/meta on a deep clone → IPC send backupWriteObj(chunk, isLast)
       emit progress
  5. emit {file: path} then complete

restore(path) → Subject<RestoreEvent>
  1. listen Channel.restoreReadObj  (main pushes one object at a time)
  2. IPC send restoreInit(path)
  3. index 0 must be metadata; check isBackupCompatible(version)
  4. on first chunk: wipe ALL in-memory collections (findAndRemove + clear indices)
  5. insert each chunk into its collection (created if missing)
  6. when restoredDocs === metadata.totalDocs:
       persist(true) → complete → setExistingVersion(backup version)
  then DesktopSyncService.restore(): clear recalculation flag, persist, location.reload()
  → on reload, migrations run from the backup version to the current one

Setting the installed version to the backup version is what makes old backups forward-compatible: the normal migration pipeline upgrades them on the next start.

Extension (ExtensionSyncService)

backup() builds a JSON file <date>_v<version>.history.json with syncDateTime, all activities and the athlete model, and saves it with file-saver. Streams and user settings are not included. restore() validates version and non-empty activities, clears activities, streams, sync time and athlete, then inserts the backup and flags localStorageMustBeCleared.

Desktop migrations

Files: desktop/migration/desktop-migration.service.ts, desktop-registered-migrations.ts, one folder per migration (upgrade_7_0_0-beta.3, upgrade_7_0_0-beta.5, upgrade_7_2_0).

upgrade()
  existing = ipcStorage["version"], package = AppPackage.getVersion()
  ├─ no existing         → firstInstall = true
  ├─ existing == package → nothing
  ├─ existing < package  → applyUpgrades(existing, package)
  │     for migration in DesktopRegisteredMigrations.LIST (ordered, oldest first):
  │        if semver.lt(existing, migration.version): await migration.upgrade(db, injector)
  │        if migration.requiresRecalculation: remember its version
  │     if any requires recalculation AND activities exist: ipcStorage["recalculateRequestedBy"] = version
  │     persist(true)
  ├─ existing > package  → reject {reason: "DOWNGRADE"} → dialog, continue
  └─ finally ipcStorage["version"] = package
DesktopAppService.init() later reads recalculateRequestedBy and runs recalculateAll().

A migration extends DesktopMigration and receives the raw LokiConstructor and the Angular Injector. It can mutate collections directly or resolve services. 7.2.0 is an example of a migration that only requests recalculation. The extension has no equivalent migration framework.

Migration caveats
  • Migrations are not bounded by the target version, only by the source version. Every registered migration newer than the installed version runs, including ones above the package version if the list is ahead.
  • No rollback. If migration N fails, earlier ones have mutated memory. The version is not updated, so they run again on next start: migrations must be idempotent.
  • Migrations operate on untyped Loki collections, so a model rename is not caught by the compiler.
